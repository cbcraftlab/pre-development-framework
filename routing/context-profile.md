# 项目与团队输入

每个项目重新输入团队信息，不继承固定人数、姓名、A/B/C 模式或能力假设。用户可以只提供人数与职责；期限、可用时间、能力、并行容量和分工偏好均可补充，未知值不伪造。

必须区分：

- 用户指定职责：本次既定分工，以及哪些职责允许建议调整。
- 能力事实与可用性：有证据的能力、时间和协作限制。
- 框架建议：任务分配、协作、依赖与工作量风险，批准前不是既定职责。

先识别合理的业务边界，再将切片和任务映射到用户指定职责。五个业务模块可以由三人承担，也可以由同一人全栈负责，不等于需要五个部署服务。尊重既定团队与系统边界，不因理论上的更优分工擅自重构产品。

输出任务负责人、协作者、契约确认方、联调负责人及验收责任；可以用稳定角色 ID 代替姓名。发现重叠、空缺、单点依赖、能力或期限冲突时，说明影响并给出调整建议，由用户决定。团队变化只更新受影响的任务映射、依赖与授权，不自动重做业务架构。

输入使用 [项目上下文模板](../templates/00-project-context.json)。`assignment_policy=fixed` 保持指定职责；`propose_changes` 允许提出调整但不视为批准。`confirmed_responsibilities` 记录用户已确认职责；任务中的 `responsibility` 必须在负责人已确认职责内，才能授权。
