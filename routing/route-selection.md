# 路线选择

先选择工作模式，再按本次变化的风险确定分析深度；两者独立。

| 工作模式 | 输入与输出 |
| --- | --- |
| new | 新项目：从 PRD 建立必要业务基线，未选技术不伪造为事实 |
| enhancement | 存量新增：读取受影响的现有行为和契约，只补新增能力 |
| delta | 已有需求变更：引用明确版本的基线，列新增、修改、删除、保留及失效范围 |

| 路线 | 适用情况 | 必须保留 |
| --- | --- | --- |
| light | 局部可逆且不改变关键业务语义 | 目标、范围、影响、任务、验收与未知项 |
| standard | 普通功能或使用已有契约的跨模块接入 | 受影响规则、入口、数据来源、契约、失败状态、切片和依赖 |
| complete | 新的跨边界状态/事务模型、资金/权限等高后果变化、关键迁移或整体边界未知 | 适用系统视图与通信、一致性、恢复、质量属性和独立复读 |

使用两个模块或一个外部 API 本身不自动升级完整路线。先判断是否改变契约、信任边界、一致性或不可逆规则。调用已有且经核实的查询接口，可以保持标准路线并补调用失败检查；新增支付回调或修改权限必须完整分析受影响链路。

深度按受影响风险决定，不按工时决定；不确定的风险先标为未知。路线升级只补新增风险要求，已核实且未失效的内容引用复用。每项裁剪说明理由，不强制为所有不适用主题生成空表。轻量产物可合并，不降低风险检查。

框架通用主干适用于软件需求准备。Web、移动端、游戏、批处理、数据/AI 系统等按需求选择相应视图；不能把多服务、页面、数据库或人工审批作为每个项目的必选架构。特殊领域的专业判断应列出所需责任人和证据，不能由通用模板自动宣布满足。
