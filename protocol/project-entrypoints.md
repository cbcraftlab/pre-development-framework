# 项目入口与准备包

项目原有 README、文档入口和开发流程继续有效。框架只追加一个导航链接，不把根 README 改成准备包专用文档，不要求复制包状态到多个文件。

一个项目可同时包含多个准备包。项目入口索引列出各包 ID、路径、适用范围及替代关系；每个包清单是其版本、状态和授权的唯一机器入口。当前工作记录可指向多个包，不要求与每个包具有相同元数据。

`entrypoints` 为可配置的项目内相对路径列表；没有既有入口时可采用 README.md 和 docs/00-current-state.md。每个已登记入口应包含该包的导航路径，而非强制含完整状态。历史包可通过索引访问，不因新包出现而删除历史事实。

准备包内的 Markdown 负责业务解释，`delivery-plan.json` 负责稳定 ID、任务依赖、负责人和验收映射；同一事实只在一个位置维护，正文引用 ID。HTML 是从源 Markdown 和结构化交付计划共同生成的阅读版，附上任务、验收、契约与授权表，携带清单、全部登记源文件与本地图的指纹；不能独立修改业务结论。

跨机器时稳定 `project_id` 与相对 `package_path` 不变；本机绝对根目录只作为运行校验参数，不写成准备包身份。实际输出必须位于用户指定根目录，移动准备包不会免除路径包含与链接安全检查。
