# 开发准备包自验规范

## 1. 自验边界

自验检查的是开发前置准备包，不检查尚未产生的正式代码，也不替代后续产品验收、测试或客户效果评价。

## 2. 十步自验

### V1 范围自验

- 是否停在 Development Ready；
- 是否误入编码、测试执行、发布或运维控制；
- 是否错误指定 Skill、Agent、工具或内部实现；
- 是否遗漏会影响多人协作的跨边界约束；
- 正式准备包是否位于目标项目内，而不是框架仓库、公共暂存区或项目外路径；

### V2 事实与假设自验

- 事实、决策、假设、未知和阻塞是否分开；
- 重要外部材料是否可追溯；
- 权威、辅助和排除来源是否互斥；
- 来源自身状态与本次权威等级是否分开；
- 历史资料是否遵循默认不继承；
- 推断是否标明依据和置信度；
- 需求冲突是否显式保留。

### V3 完整性自验

按 `checklists/system-view-matrix.md` 判断适用视图，并确保每项有结论、待办或不适用理由。

### V4 一致性自验

- 术语是否统一；
- 需求、流程、规则和状态是否冲突；
- 模块、入口和数据所有权是否唯一；
- 时序、交互条目和正式契约是否一致；
- 架构图、通信模式、交互目录和正式契约是否一致；
- 任务依赖和切片顺序是否一致；
- 验收条件是否对应原始目标。

### V5 跨模块自验

使用 `checklists/interaction-review.md` 检查循环依赖、隐式共享、无主流程、接口所有权、通信模式、事务一致性、页面读聚合、失败补偿和跨人文件所有权。

### V6 异常和反例自验

对适用链路追问：失败、超时、重复、并发、乱序、取消、部分成功、权限不足、外部系统不可用和写入后下一步失败时会怎样。

### V7 追踪自验

对关键需求检查：

```text
需求 -> 规则/状态 -> 流程 -> 模块 -> 通信/交互/契约 -> 任务 -> 验收
```

任一必需节点断链时不得 Ready。

### V8 可执行性自验

采用隔离上下文复读：让不了解前期讨论的开发者或新模型只阅读准备包，并回答：

- 做什么和不做什么；
- 从哪里开始；
- 依赖什么；
- 哪个模块负责；
- 遵守什么契约；
- 如何判断完成；
- 遇到未知项何时停止。

需要原作者现场解释时，自验失败。

### V9 过度约束自验

使用 `checklists/model-autonomy-review.md` 删除不必要的私有函数、局部变量、类结构、工具、Skill、Agent 数量和调试方法约束。

### V10 结论自验

- 结论是否符合质量门而非主观乐观判断；
- 未验证事项是否明确；
- Condition 是否具有责任人、期限和回退影响；
- 使用的框架版本、路线和裁剪理由是否记录；
- 包清单中的身份、版本、路线、Ready 结论和产物列表是否与正文一致。
- 基线状态、可开发范围和批准记录是否与 Ready 结论一致；
- 项目入口、清单和正文是否一致；
- 已关闭澄清项是否完成全链影响回写。

## 3. 自验独立性

起草者可以完成第一轮自验，但完整路线在正式使用前应至少进行一次隔离上下文复读。框架候选版的验证还需要固定案例和真实项目试点，不能用准备包自验代替框架自身验证。

## 4. 输出

自验结果使用 `templates/10-self-validation-report.md`，只允许 `Ready`、`Conditionally Ready`、`Not Ready` 或 `Invalid Input` 四种结论。

新版检查：入口导航有效即可，不复制包元数据；状态按切片质量、批准与授权分别检查。任务/需求/验收/契约引用、团队已确认职责及阅读版指纹由校验器检查，业务一致性仍需语义复核。
