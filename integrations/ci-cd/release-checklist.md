# 项目发布接入与验收清单

此清单是可选配套，不是需求包授权记录。按目标项目逐项填写责任人、证据位置、提交/镜像 digest、环境和时间；未验证项保持未验证。

## 接入前

- [ ] 已获得在指定仓库/环境安装 CI、创建 package、配置凭据及部署的明确授权。
- [ ] 已核对现有流水线和文件，未覆盖用户配置；编译、前端/后端测试命令真实存在且失败能阻断后续阶段。
- [ ] PR 无部署凭据和镜像写入；main 受保护，required check 名称与实际结果一致。
- [ ] test/production 分离；生产人工审批真实存在、符合套餐能力和组织要求，不能仅凭 YAML 环境名认定。
- [ ] kubeconfig 及镜像拉取凭据最小授权；runner 能访问目标环境；集群、Deployment、容器名称和健康端点已核对。
- [ ] 已确认本次 schema/数据变更及先后顺序；模板不代跑迁移。有迁移时先停用测试自动部署，完成兼容迁移再发布。
- [ ] 已保存发布前两个组件的实际 digest；旧版本对迁移后的数据仍兼容；有受权回滚执行人。

## 隔离环境演练

- [ ] PR、main、手动触发分别验证；在 PR 中修改 Dockerfile/工作流仍不会上传或部署。
- [ ] Go 或前端测试失败会阻断发布；Docker 构建失败会阻断部署。
- [ ] 缺少 Secret、环境变量或生产确认时停止；错误分支不能通过手动触发部署。
- [ ] Action/依赖更新、共享文件、Dockerfile、删除/重命名仍能覆盖正确组件；无法确定影响时全量构建。
- [ ] 同环境部署串行；理解排队可能被新请求替换；其他部署入口共用相同并发规则。
- [ ] 故意设置一个错误镜像，确认超时/失败会报错；记录部分更新后的处理，不把失败当自动回滚。
- [ ] 按旧 digest 完成回滚演练并重做健康与最小业务验收。

## 每次发布

- [ ] 本次提交、批准记录、两个新 digest、旧 digest、目标环境及迁移状态均可追溯。
- [ ] 迁移与镜像兼容性、后台任务和外部依赖已核对；生产审批覆盖本次具体变更。
- [ ] rollout 状态、健康端点和关键业务验收分开记录；真实用户效果未验证时明确写出。
- [ ] 发布失败时核对实际运行版本与数据状态，再按受权方案修复或回滚。
- [ ] 记录失败、回滚、未验证项和后续责任人；不把“CI 绿色”写成业务验收通过。
