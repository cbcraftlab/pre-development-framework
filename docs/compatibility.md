# 版本与兼容政策

当前候选版 `0.10.0-candidate.2`。框架版本、需求包版本和产品版本分别记录。

| 输入包版本 | 当前处理 |
| --- | --- |
| 0.10.0-candidate.2 | 当前格式与全部当前结构检查 |
| 0.10.0-candidate.1 | 字段兼容，使用加强后的验收/图/HTML 检查；须重建 HTML |
| 0.9.0-candidate.5 | 冻结旧校验和旧 Schema，不获得新版保证 |
| 其他版本 | 明确报错，不猜测格式或静默迁移 |

新包由模板写入当前版本；同一包的上下文与清单须使用相同框架版本。新版增加可选 readable_title，自定义标题成为清单事实；HTML 从当前生成器完整重建，不能修改 HTML 后保留旧指纹冒充同步。

candidate.1 包无需伪改版本即可使用新检查：保留原版本、运行当前生成器、复核新增检查指出的问题。正式迁移按 [增量协议](../protocol/change-and-evidence.md) 记录语义和批准影响。

候选期收紧错误放行的检查要在 CHANGELOG 记录原行为、影响与恢复方法。字段、语义和支持版本变化须补正负例，冻结旧规则不受顺手重构影响。未来稳定版明确支持窗口和迁移方法，不承诺永久支持所有候选格式。

模型行为、项目效果和批准真实性均不是格式兼容性所能证明的事实。

仓库文本采用 LF，.gitattributes 固定检出换行，避免 Windows 自动换行改变来源字节和派生指纹。复制或迁移项目包时保留原始字节；确需改变来源换行时重新生成阅读版。
