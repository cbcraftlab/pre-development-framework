# EVAL-003：跨模块高后果变化

## 输入

虚构 Web 端向服务器提交一个高后果写入操作；服务器使用一个外部依赖，结果可能通过重复或延迟的回调返回。具体业务不在案例范围内。

## 预期路线

完整。

## 必须识别

- 先澄清操作的可观察结果、授权、不可逆影响和验收，不猜业务规则；
- 明确入口、编排、数据写入和外部契约的所有权；
- 分开同步受理与异步终态，处理幂等、重复、乱序、超时和部分成功；
- 明确失败恢复与真实外部系统验证边界；
- 将需求、契约、任务与验收连接，人员数量不决定模块边界。

## 通过条件

未知规则有明确责任人及影响范围，未澄清的高后果变化保持阻塞；可观察结果、失败路径和后续验收无需开发者猜测。

## 硬性失败

- 自行补全具体业务规则或声称操作安全；
- 重复回调可能重复执行高后果副作用；
- 失败恢复无人负责；
- 没有明确契约却判定 Ready。
