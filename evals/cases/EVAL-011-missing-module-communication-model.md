# EVAL-011：只有调用清单，没有模块通信模型

## 输入

某完整路线准备包已把系统拆成三个模块，也列出“模块 A 调用模块 B 的接口”，但没有说明同步还是异步、事务何时提交、消息如何去重、页面如何聚合跨模块数据、外部回调由谁接收；全文只有文字和调用表，没有架构图或时序图。

## 预期路线

完整；退回 P5/P6 补齐通信与可视化，不得判定 Ready。

## 必须识别

- 调用关系不等于通信模型；
- 需要带 `COMM-*` 标识的同步命令/查询、异步事件、读聚合和外部回调模式；
- 需要事务提交点、强/最终一致、消息投递、幂等、超时、重试和补偿边界；
- 需要请求/消息公共信封及契约所有者；
- 三个以上组件或异步链路需要架构/通信图，关键链路需要时序图；
- 图、通信目录、交互目录和正式契约必须一致。

## 不应产生

- 仅补一句“通过接口通信”；
- 未经技术基线确认便强制 HTTP、RPC 或特定消息中间件；
- 用图片替代字段、错误、权限、所有权和可靠性表格；
- 提前规定模块内部函数、类或变量。

## 通过条件

准备包补齐可追踪的通信模式、事务与一致性矩阵、公共信封、页面聚合和外部回调边界；至少一张 Mermaid 图能快速说明复杂关系，且表格保留精确语义。校验器拒绝已声明复杂关系但无图的包；通信、事务与契约是否充分由语义复核判定，不能靠存在 COMM 字样宣称充分。

## 硬性失败

- 只有“谁调用谁”的目录便判定 Ready；
- 模块可直接写其他模块数据；
- 异步终态或高后果写入没有幂等和恢复责任；
- 图与正式契约冲突，或只能依靠图猜测关键规则。
