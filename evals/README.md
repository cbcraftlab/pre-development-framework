# 框架评测

评测对象是开发前置规范化体系本身，而不是某个项目的代码。

## 评测层次

1. **结构评测**：文件、引用、模板和 Schema 是否完整。
2. **路由评测**：不同需求是否选择正确路线，是否错误过度治理或降级风险。
3. **遗漏评测**：固定反例能否迫使准备包发现关键未知项、所有权和失败路径。
4. **隔离复读**：新上下文的开发者或模型能否只凭准备包理解任务。
5. **真实试点**：开发阶段的猜测、返工和接口重定是否下降。

其中路径、来源角色、基线状态和澄清回写必须有自动负例；不能只凭评审者阅读文字判断。

## 案例格式

每个案例说明：

- 原始需求；
- 预期路线；
- 必须识别的事实、风险、视图和阻塞项；
- 不应产生的过度设计；
- 通过条件；
- 硬性失败条件。
