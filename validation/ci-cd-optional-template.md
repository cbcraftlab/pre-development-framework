# 可选 CI/CD 模板验证记录

日期：2026-10-27。本记录覆盖可选配套的本地验证，框架版本及需求包格式保持 `0.10.0-candidate.2`，未单独发布新版本标签。

## 范围

新增虚构 Web＋Go 服务的 GitHub Actions 示例、可选 Kubernetes 适配器和接入/发布检查清单。补 README、总体框架导航和未发布变更记录；仓库门检查配套文件存在，回归发现器自动包含新适配器测试。本仓库实际生效的 `.github/workflows/validate.yml` 保持不变。

PR 在只读 job 内测试及构建；单独的 main 发布 job 才获得 packages 写权限。部署使用本次构建的 digest，测试自动部署默认关闭，生产需手动选择、显式确认、启用环境及另行配置审批。模板保守全量构建两个组件，不引入增量判断的漏构建路径。框架继续在 Development Ready 交付处停止。

## 未验证与采用条件

- GitHub 托管 Linux/macOS/Windows CI 的实际结果以[对应提交的 Actions 记录](https://github.com/cbcraftlab/pre-development-framework/actions/workflows/validate.yml)为准。本记录中的 macOS 本地结果和旧基线 CI 不替代本次提交的托管验证；框架 CI 也不等于运行了示例项目的镜像/部署流程。
- 没有合成业务应用或真实目标项目云端试跑；未实际构建/上传 GHCR 镜像、连接集群、读取用户 Secrets、发布、迁移或回滚。模板必须先适配并完成隔离环境演练。
- 适配器单测不证明 Kubernetes 版本兼容、网络、RBAC、探针、镜像拉取或业务验收。两个 Deployment 更新不具备原子性；失败不自动回滚。
- 手动确认文本和环境开关不等于独立审批。生产 required reviewers 等规则须在支持该能力的 GitHub 套餐/仓库设置中真实配置；无法满足审批要求时保持生产关闭。
- 数据库迁移不由模板执行或检测。含迁移的改动必须先停止自动部署并完成项目规定的兼容迁移与审阅，再发布对应版本。

Git 交付按明确授权提交配套范围、推送并核对实际 CI；仅同步框架不会启用示例工作流。目标项目接入与真实部署仍需各自单独授权和验收。
