# Candidate 2 轻量输出规则审计

- 框架版本：`0.9.0-candidate.2`
- 审计范围：项目内输出位置与最小准备包清单
- 当前状态：结构自验通过，可进入真实项目试点

## 目标

把“开发准备包跟随具体项目”落实为最小可试用规范，同时避免在真实需求出现前强制设计完整的版本治理系统。

## 当前保留

- 默认输出到 `<project-root>/docs/pre-development/<package-id>-<package-slug>/`；
- 允许项目在自身根目录内显式调整输出位置；
- 未确认项目根目录时不生成正式准备包；
- 每个正式准备包包含简化的 `package-manifest.json`；
- 清单只记录框架版本、包 ID、短名、包版本、路线、Ready 结论和产物路径列表；
- 轻量路线仍可以合并产物，不强制固定文件数量。

## 暂不强制

以下能力在真实试点证明有必要前，不作为候选版硬规则：

- 文件哈希；
- 历史快照和版本冻结；
- 完整准备包生命周期状态机；
- 归档目录；
- 既有文档与跨项目迁移流程；
- 面向真实项目准备包的独立命令行工具。

## 验证证据

执行：

```text
python3 scripts/validate_repository.py
```

结构校验覆盖：

- 协议、清单模板和 Schema 存在；
- Markdown 本地链接有效；
- 四组 JSON 模板与 Schema 结构相符；
- 框架版本在入口和机器模板中一致；
- 清单目录名可由包 ID 与短名稳定推导；
- 产物路径是准备包内的安全相对路径且不重复；
- 框架仓库没有误放真实项目清单；
- 既有六个评测案例和执行自主边界继续有效。

## 结论

结论：**轻量输出规则结构自验通过。**

该结论只说明候选框架已经具备一致的项目内输出位置和最小机器入口。它尚未证明不同模型能稳定使用这套规则，也未证明准备包能减少真实开发返工；这些问题必须通过真实项目试点评判。
