# 0.10.0-candidate.1 升级与验证记录

日期：2026-09-08。目标：将 PRD 与项目现状、本次团队人数和职责，转换为可领取、可验收的开发准备包。范围仅为 pre-development-framework；本次未修改试点项目或执行 Git 操作。

## 交付结论

候选版升级已完成，可以进入真实 PRD 试用。机械规则和合成样例验证通过；尚不能声称适用于所有项目，或已经证明减少开发返工。保留候选状态。

## 本次变化

1. new / enhancement / delta 工作模式与 light / standard / complete 风险路线分开。使用已有接口不因跨模块数量自动升级完整流程。
2. 人数、可用时间和职责按项目输入，区分用户已确认分工与模型建议。业务边界不按人数强拆，允许一人兼任多种责任。
3. 分开记录产品期望与实际现状，保留来源版本、核验时间、适用范围和失效条件。每条需求须有权威规范性来源支持期望行为。
4. 分开材料就绪、批准与授权。允许 candidate + ready + none；独立已就绪切片不受无关阻塞拖累。批准版本与授权依赖受机械检查。
5. 使用稳定项目 ID、相对路径和可配置多包索引，保留项目原有入口内容。
6. 新增 delivery-plan.json 与 Schema，检查任务引用、依赖环、验收覆盖、职责、契约确认登记和切片授权。阅读版自动附带结构化表格，并检查来源漂移。
7. 保留冻结旧版兼容校验，增加三种工作模式的合成样例与七组行为评测规格。

## 未完成的验证与限制

- 浏览器工具访问合成包本地 file 地址被 URL 安全策略拒绝。没有改用其他浏览器、代理或间接执行绕过；HTML 的实际屏幕排版和视觉可读性尚未核验。
- EVAL-013—019 已写为评测规格，尚未由独立模型或人员实际执行。当前起草者检查不冒充独立复读。
- 三个样例的 PRD、接口、人员与基线均为明确标注的合成输入，不是真实业务批准，也不证明接口存在。
- 机器检查无法证明产品语义、来源真实性、批准真实性、契约充分性和条件隔离成立。哈希是漂移检测，不是签名或审批系统。
- 旧版兼容只保留旧检查，不获得新版覆盖保证。迁移需明确映射，不能只替换版本号。
- 真实项目耗时、澄清次数、开发中重新定义需求/契约的次数及返工是否下降，仍需后续记录。

## 下一步使用

选择一份真实 PRD，提供项目属于新建、存量新增还是需求变更，以及本次团队人数和各自职责。使用新版产生一个有明确范围的准备包，再由未参与起草者仅凭包内容复读。依照验证计划记录遗漏、澄清和流程成本；只有出现实际问题才调整对应规则。
