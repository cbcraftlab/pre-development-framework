# 跨模块交互审查清单

## 所有权

- [ ] 每条端到端流程有唯一编排负责人。
- [ ] 每个公开能力、接口和事件有唯一契约所有者。
- [ ] 每个核心数据对象有唯一写入语义所有者。
- [ ] 每个页面、API、任务和回调有唯一组装主责。
- [ ] 没有两个人长期共同拥有同一页面或实现文件而边界不清。

## 依赖

- [ ] 模块依赖方向能够解释且没有未处理循环。
- [ ] 调用方不直接访问提供方私有表、类或内部状态。
- [ ] 同步调用链长度与失败传播能够接受。
- [ ] 查询和命令语义没有混用。
- [ ] 异步事件表达已发生的事实，而不是含糊通知。
- [ ] 业务语义与传递模式分开说明，没有把“事件”等同于某个消息中间件。
- [ ] 页面/API 的跨模块读由唯一聚合主责通过公开查询或读投影完成。
- [ ] 浏览器、页面或模块没有直接跨域写库或自行编排多个私有实现。

## 可靠性

- [ ] 重复请求或重复事件的行为已定义。
- [ ] 超时由哪一方处理已定义。
- [ ] 重试责任、次数和退避语义已定义。
- [ ] 乱序、丢失和延迟事件按适用性处理。
- [ ] 部分成功和补偿责任已定义。
- [ ] 状态提交点和外部调用顺序可解释。
- [ ] 数据库提交与消息投递之间使用可恢复模式，或明确说明不适用理由。
- [ ] 同步请求和异步消息具备 Trace、租户、幂等及版本所需的公共语义。

## 契约

- [ ] 输入输出只包含跨边界所需数据。
- [ ] 错误、拒绝和状态变化语义明确。
- [ ] 权限、租户或信任边界明确。
- [ ] 兼容、版本和废弃策略按适用性明确。
- [ ] 契约足以支持Mock、并行开发和后续契约测试。

## 追踪

- [ ] 每项交互能追踪到业务流程和需求。
- [ ] 每项交互能追踪到开发任务和联调场景。
- [ ] 时序图、交互目录和正式契约没有冲突。
- [ ] 复杂拓扑、跨模块时序、状态或依赖已有相应图，不依赖长段文字才能理解。
- [ ] 图中的关键关系可追踪到 `COMM-*`、`INT-*`、`CON-*` 或 `FLOW-*`。
- [ ] 图、通信目录、交互目录和正式契约表达一致；图不是正式语义的唯一载体。
