# 一致性与追踪审查

- [ ] 同一术语在需求、流程、模块和契约中含义一致。
- [ ] 原始需求与已批准变更均可追溯。
- [ ] 权威、辅助和排除来源集合互斥，历史资料没有默认继承。
- [ ] 状态机允许的动作与页面/API能力一致。
- [ ] 业务规则与验收条件相互对应。
- [ ] 模块责任卡与入口归属表一致。
- [ ] 数据所有权与架构数据模型一致。
- [ ] 交互目录与时序图一致。
- [ ] 通信模式目录与拓扑图、时序图一致。
- [ ] 正式契约与交互目录一致。
- [ ] 图中的关键节点和边能关联稳定 ID，且没有引入表格/正文未声明的决定。
- [ ] 交付切片没有遗漏必要模块或契约。
- [ ] 开发任务覆盖切片且依赖无循环。
- [ ] 关键需求从需求到验收没有断链。
- [ ] 未知项、决策和假设在所有相关产物中状态一致。
- [ ] `package-manifest.json` 中的包身份、版本、路线和 Ready 结论与正文一致。
- [ ] 清单登记的正式产物路径唯一、存在且未逃逸准备包目录。
- [ ] 清单项目身份稳定、路径相对化，实际准备包位于本次指定根目录内。
- [ ] 项目入口导航有效；包正文摘要与清单版本、状态一致；入口无需复制这些状态。
- [ ] 每个已关闭澄清项的受影响 ID 均在回写清单中出现。
- [ ] HTML 阅览版由 Markdown 事实源生成，版本/状态一致，不存在手工维护的第二套结论。
- [ ] Markdown 表格在阅览版中呈现为真实表格，本地图可见且引用有效。

新版检查：入口导航有效即可，不复制包元数据；状态按切片质量、批准与授权分别检查。任务/需求/验收/契约引用、团队已确认职责及阅读版指纹由校验器检查，业务一致性仍需语义复核。
