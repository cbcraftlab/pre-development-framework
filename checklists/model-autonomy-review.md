# 开发执行自主性检查

前置准备包应删除或解释以下约束：

- [ ] 强制使用指定模型。
- [ ] 强制使用指定 Skill。
- [ ] 强制使用单Agent或多Agent。
- [ ] 强制使用某种调试、浏览器或测试工具。
- [ ] 无架构理由地指定私有函数名称。
- [ ] 无跨边界意义地指定局部变量。
- [ ] 无必要地规定内部类、目录或文件拆分。
- [ ] 把“建议”写成不可变要求，却没有业务或技术依据。
- [ ] 把某个模型当前能力限制固化为长期产品边界。

以下约束可以保留：

- 已确认的业务行为和验收结果；
- 模块、数据和入口所有权；
- 跨边界接口、事件和兼容规则；
- 安全、权限、精度、事务和不可逆操作约束；
- 有明确理由的技术栈、部署环境和组织硬约束；
- 后续必须证明的性能、可靠性和测试结果。

判断标准：换一个更强的大模型后，这项约束是否仍然必要？如果答案是否定的，通常不应写入前置强约束。
